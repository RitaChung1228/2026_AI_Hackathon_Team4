一般性使用規範與限制
1. 請勿建立公開對外的 S3 Bucket,請透過 S3 Block Public Access 或 S3 Bucket Policy 來
限制公開存取。
2. 參賽隊伍同意在黑客松期間使用 AWS 帳戶時,不會在 AWS 帳戶中使用/匯入/輸入/引入
任何包含以下內容的資料或資料集:1/ 個人資料;2/ 受管制資料;3/ 財務資訊;4/ 有關
種族或民族的資訊;5/ 有關政治觀點的資訊;6/ 有關宗教或哲學觀點的資訊;7/ 有關工
會會員資格的資訊;8/ 基因資料;9/ 生物識別資料資訊/生物識別識別符;10/ 有關性取
向或性生活的資訊;11/ 健康資料;12/ 付款處理資料;或 13/ 惡意程式碼/惡意軟體。
3. 請勿建立 Security Group 對外完全開放的 EC2 執行個體。
4. 請勿建立啟用公開存取的 RDS 執行個體或 EMR 叢集。
5. 基於資源有效利用原則,參賽隊伍應限制在帳戶中啟動之執行個體數量,僅限於必要工作
所需,以避免不必要之資源浪費。
6. 參賽隊伍應以 us-east-1 與 us-west-2 兩個區域作為部署之指定主要區域。
7. 競賽環境所支援的 AWS Services 請參閱附件中的「Supported AWS Services List
20260722.xlsx」 的 Services List 工作表。
8. 參賽者在將程式碼上傳至 GitHub 或任何公開儲存庫時,請務必確認未包含任何機密憑證
資訊(如 AWS Access Keys、API Tokens、資料庫密碼等),建議善用 .gitignore 與環
境變數管理機密資訊。
9. 若有使用 Kiro 之參賽者:上傳至 GitHub 或任何公開儲存庫時,必須在專案根目錄包含
/.kiro 資料夾,以展示 specs、hooks 和 steering 的使用情況。請留意勿將 /.kiro 資料夾
或其子資料夾加入 .gitignore。
Amazon Bedrock 規範與限制
1. 參賽隊伍需控制 Amazon Bedrock 的請求限制在每秒 1 個請求以下(RPS/TPS)。
2. 參賽隊伍應秉持資源有效利用原則,僅針對當前專案直接相關之 Amazon Bedrock 模型
申請必要的模型存取權,請勿無目的地大量啟用所有可用模型。
3. 參賽隊伍有責任定期檢視已獲存取權之模型使用狀況,定期檢閱並撤銷不再使用的模型的
存取權。
Amazon EC2 and Amazon SageMaker AI 規範與限制
黑客松比賽期間對 EC2 及 SageMaker AI 可用的執行個體有限制類型,可以使用的資源與限制請
參考附件中的「Supported AWS Services List 20260722.xlsx」的 EC2 及 SageMaker AI 工作
表。基於資源調配及優化考量,該限制可能會依實際情況進行調整,請以黑客松競賽期間所提供
之實際環境為主。

同時鑒於黑客松比賽時間與計算資源之有限,不建議參賽隊伍於本次黑客松競賽中在 AWS 平台
上進行大規模模型訓練作業。
注意事項
上述所列各項規範與限制可能因應實際比賽與資源使用情況而有所更動,且上述資訊可能未能充
分涵蓋所有限制事項,因此請以競賽期間提供之實際環境或公告為最終依據。

參賽隊伍如有任何疑問,敬請於競賽期間向黑客松工作人員諮詢。
